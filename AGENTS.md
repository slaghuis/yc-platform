## Feature Development Workflow

When asked to develop a new feature or enhancement:

1. Read the relevant feature specification in `docs/features/`.
2. Inspect the existing codebase before proposing a solution.
3. Identify affected components, data models, APIs, and dependencies.
4. Summarise the proposed implementation plan before making code changes.
5. Identify security implications, edge cases, and required tests.
6. Implement in small, verifiable steps.
7. Run the relevant tests and checks.
8. Update documentation and the feature specification if the implementation changes any agreed requirements.

Do not assume that a feature specification overrides existing security requirements or established architectural constraints. Raise ambiguities before making consequential design decisions.
